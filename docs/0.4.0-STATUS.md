# VISER 0.4.0 Development Status

## Scope
0.4.0 establishes the cross-platform desktop foundation for Windows and macOS. It does not claim a complete video editor or autonomous production system.

## Implemented in this development pass
- Added Tauri 2 desktop project scaffold alongside the existing React/Vite application.
- Added Tauri CLI and JavaScript API dependencies.
- Added native runtime information command (OS, architecture, app version and FFprobe availability).
- Added native folder picker and recursive local media file discovery.
- Added an explicit 10,000-file scan cap, symlink skipping and common generated/system folder exclusions.
- Added a native media library view to the desktop UI.
- Added app identifier, desktop window sizing, Windows NSIS and macOS DMG bundle targets.
- Added minimal dialog permission.
- Updated product naming and package version to 0.4.0.
- Added Windows/macOS CI matrix with Rust and frontend validation.

## Verified
- Existing TypeScript typecheck passes.
- Existing 11 core unit tests pass.
- Vite production build passes.
- Tauri CLI scaffold and config files generated.
- Rust stable toolchain installed on the Windows development machine.
- MSVC Build Tools and Windows 11 SDK installation initiated/completed sufficiently to locate the compiler and SDK libraries.

## Outstanding blockers / incomplete acceptance criteria
- Local Rust compilation is currently blocked by the Windows SDK linker environment: `link.exe` is found, but `dbghelp.lib` is not present in the installed SDK paths. Install the Windows SDK Debugging Tools component or repair the SDK component selection, then rerun `cargo check`.
- Tauri native app has not yet been launched or visually verified.
- Native folder discovery currently returns file names, paths, extensions and byte sizes only. It does not yet run FFprobe or create the canonical MediaInventory schema.
- Thumbnail extraction, actual video playback, seeking, interactive timeline, SQLite persistence, undo/redo and proxy generation remain incomplete.
- macOS native build must be verified on a macOS runner; Windows development cannot prove macOS runtime behavior.

## Important implementation boundary
The native media scan is read-only. It skips symbolic links, ignores common generated directories and caps discovery at 10,000 files. It does not upload or modify source media.
